# Idb.Analyzers

Roslyn diagnostics for immutable InterfaceDB contract baselines and avoidable query scans.

The package works through the standard .NET analyzer mechanism used by Visual Studio, VS Code C# tooling, Rider, `dotnet build`, and CI.

It requires Roslyn 5.9 or newer. Use .NET SDK 10.0.401 or newer for command-line builds
and an IDE with a Roslyn 5.9 or newer compiler host for editor diagnostics. Older
compiler hosts report CS9057 and skip this analyzer; database runtime behavior is
unaffected. The repository's global.json selects the required SDK.

Checks run during both Debug and Release compilation so a release build cannot silently bypass
contract-baseline validation. They are compiler tooling and do not execute in the running database.
The repository's CI treats `CS9057` as an error; update the compiler host instead of disabling analyzers.

Rules:

- `IDB001`: a recorded contract was removed, renamed, or moved.
- `IDB002`: a storage contract has no baseline manifest.
- `IDB003`: an existing baseline version was changed in place.
- `IDB004`: a baseline manifest is malformed.
- `IDB005`: a prefix/suffix search on a known indexed string member uses a non-ordinal comparison.

`IDB005` applies to inline InterfaceDB search predicates and direct indexed members.
It excludes encrypted/unindexed members and index modes without the corresponding
prefix/suffix index. It does not guess the value of a runtime comparison variable.
The default string index supports exact and prefix matches, so default-index
`EndsWith` calls do not trigger this warning. A suffix warning requires an explicit
member mode that includes `Suffix` (for example, `SearchIndexMode.All`).
Use `StringComparison.Ordinal` only when ordinal comparison is the application's
intended behavior; otherwise keep the comparison and suppress the performance
warning locally. No automatic code fix changes string semantics. This diagnostic
does not run inside the database or affect query execution.
Projects that treat warnings as errors may need to address or explicitly suppress
`IDB005` when upgrading; keeping culture-sensitive semantics is a valid choice.

Baseline manifests are generated by the InterfaceDB migration tool.
